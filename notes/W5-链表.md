## 1. 本阶段的核心命题

### 1.1 一句话

> **链表 = 一堆散落在堆上的节点 + 每个节点里存着下一个节点的门牌号。**

数组靠"挨着放"找到下一个元素；链表靠"记住"下一个在哪。

### 1.2 三个必答问题

1. **节点长什么样？** → 自引用结构体，`next` 是指向同类型的指针
2. **栈上的 `head` 和堆上的节点是什么关系？** → `head` 只存**第一个**节点的地址，它不"包含"链表
3. **改谁？** → `p->next = q` 改**堆内存**；`p = q` 改**栈上的变量**

---

## 2. 链表是什么

### 2.1 结构体定义

```c
struct node {
    int  id;
    char name[20];
    struct node *next;      /* 自引用 */
};
```

### 2.2 为什么 `next` 必须是指针

```c
struct node *next;      /* ✅ 合法 */
struct node  next;      /* ❌ error: field 'next' has incomplete type */
```

如果成员是"另一个自己"，编译器要算 `sizeof(struct node)` → 里面又有自己 → **无限递归**。

指针只存地址，**恒为 8 字节**，与它指向什么类型无关，所以能打破递归。

### 2.3 内存布局（实测）

```c
printf("sizeof(struct node) = %zu\n", sizeof(struct node));   /* 32 */
printf("offsetof(id)   = %zu\n", offsetof(struct node, id));    /* 0  */
printf("offsetof(name) = %zu\n", offsetof(struct node, name));  /* 4  */
printf("offsetof(next) = %zu\n", offsetof(struct node, next));  /* 24 */
```

```
字节偏移  0        4                    24               32
        ┌────────┬────────────────────┬────────────────┐
        │  id 4B │   name[20] 20B     │   next 8B      │
        └────────┴────────────────────┴────────────────┘
```

**注意 `name` 从 4 开始不是 8**：4 正好是 `int` 的倍数，不需要 padding。但 `next` 必须 8 对齐，所以 24 之后到 32。

### 2.4 一个坑：`typedef` 里不能用别名

```c
typedef struct node {
    struct node *next;   /* ✅ 必须写 struct node */
    Node *next;          /* ❌ 编译错误：此刻 Node 还不存在 */
} Node;
```

typedef 的别名要等整个声明**结束**才生效。

## 3. 造节点：`create_node`

```c
struct node *create_node(int id, const char *name){
    struct node *a = malloc(sizeof(struct node));
    if (!a) return NULL;              /* ① 必须检查 */
    a->id = id;
    my_strcpy(name, a->name);         /* ② 复制字符串，不能 a->name = name */
    a->next = NULL;                   /* ③ 必须置 NULL */
    return a;
}
```

### 3.1 四个要点

| # | 要点 | 为什么 |
|---|---|---|
| ① | `malloc` 可能失败 | 失败返回 NULL，直接解引用就崩 |
| ② | 用 `sizeof(struct node)` 不要写 32 | 以后加字段自动适应 |
| ③ | 字符串要**复制** | `a->name` 是数组，`= name` 是给数组赋值（非法），要逐字节拷 |
| ④ | `next` 必须置 NULL | **`malloc` 给的是脏内存** |

### 3.2 为什么必须 `next = NULL`

`malloc` 返回的是"上一个使用者留下的内存"，`free` **不清零**。

忘设 `next = NULL` 的三种结局：

| 脏地址的内容 | 后果 |
|---|---|
| 不可访问 | 崩 `0xC0000005` |
| 可读的垃圾 | 打印乱码，继续跑飞 |
| **恰好是 0** | **一切正常** |

第三种最可怕——**开发机好好的，换台机器就崩**。

## 4. 插入：头插 vs 尾插

### 4.1 头插（O(1)）

```c
struct node *push_front(struct node *head, int id, const char *name){
    struct node *q = create_node(id, name);
    if (q == NULL) return head;    /* 失败也要返回原 head，不能返回 NULL */
    q->next = head;                /* 新节点接上旧链 */
    return q;                      /* 新头 */
}
```

**两步**：改新节点的 `next` + 改 `head`。

注意失败时 `return head` 而不是 `return NULL`——**插入失败，但不能把整条链丢了**。

### 4.2 尾插（O(n)）

```c
struct node *push_back(struct node *head, int id, const char *name){
    struct node *q = create_node(id, name);
    if (!q) return head;
    if (!head) return q;           /* 空链表：新节点就是头 */

    struct node *p = head;
    while (p->next) p = p->next;   /* 走到最后一个 */
    p->next = q;                   /* 改最后一个的 next */
    return head;                   /* 头没变 */
}
```

**只改一处**：最后一个节点的 `next`。`head` 完全没动。

### 4.3 一个字节的差别

```
q = head        改的是「栈上的变量 q」       → 链表没变
q->next = head  改的是「堆上的内存」          → 链表变了
```

**看起来对称，意思完全相反。**

我在这上面栽过一次：写成 `head = q->next;`——`q->next` 是 NULL，`head` 直接变成 NULL，**整条链丢了**。

### 4.4 空链表为什么能自动工作

第一次 `push_back` 时 `head == NULL`：

```c
if (!head) return q;    /* 直接返回，不进入 while */
```

而头插时 `q->next = head` 等于 `q->next = NULL`——**正好是正确值**。

> 空链表不需要特判，是因为 **NULL 在这里刚好也是对的**。

## 5. 遍历与查找

### 5.1 遍历

```c
void print_list(const struct node *head){
    const struct node *p = head;      /* 两个 const：参数 + 游标 */
    while (p) {
        printf("id=%d\tname=%s\n", p->id, p->name);
        p = p->next;
    }
    printf("the end\n");
}
```

**`p` 必须也是 `const`**——否则 `struct node *p = head` 会丢掉 const（只有 warning，保护失效）。

### 5.2 `p = p->next` 为什么不会丢掉前面

**`head` 从头到尾没变过**。`p` 是另一个变量，每轮只改自己那 8 个字节。

堆上所有的 `next` 原封不动：

```
第 1 个节点 ← head 记着
第 2 个节点 ← 第 1 个的 next 记着
第 3 个节点 ← 第 2 个的 next 记着
```

**遍历不修改链表，一个地址都没被抹掉。**

单向链表只有 `next` 没有 `prev`，所以只能往前走。

### 5.3 查找：短路顺序

```c
struct node *find(struct node *head, int id){
    struct node *t = head;
    while (t != NULL && t->id != id)    /* ← 顺序不能反 */
        t = t->next;
    if (!t) return NULL;
    else    return t;
}
```

**我最初的写法是 `while (t->id != id)`** → 空链表时 `t` 是 NULL，`t->id` 直接崩。

> **规矩：循环条件里出现 `p->xxx`，前面必须有 `p`。**
>
> 靠 `&&` 的**短路求值**保护：左边为假，右边不算。

### 5.4 返回地址 vs 返回 NULL

```c
struct node *hit = find(head, 2);
hit->id = 20;        /* 改的是堆上真节点，不是副本 */
```

**返回地址 = 告诉你书在哪，不是复印一份给你。**

找不到时返回 `NULL`——因为指针类型必须返回一个值，而链表里没有"不存在的节点"这个东西。

## 6. 删除：删除 = 跳过

### 6.1 核心思想

```
删除前：  A → B → C
删除 B：  A ────→ C
```

**只改一个指针**（`A->next = C`），B 还在内存里，只是没人指向它——所以还要 `free(B)`。

### 6.2 难点不是改指针，是拿到前驱

单向链表没有 `prev`，所以要么：

- **双指针**：`prev` 和 `cur` 一起走（我用的）
- **二级指针**：`struct node **pp`，直接改"指向当前节点的那个指针"

### 6.3 双指针实现

```c
struct node *remove_node(struct node *head, int id){
    struct node *cur = head, *prev = NULL;
    while (cur != NULL && cur->id != id) {
        prev = cur;             /* 先记！ */
        cur  = cur->next;       /* 再走！ */
    }
    if (cur == NULL) return head;      /* 没找到 */

    if (prev == NULL)                  /* 删的是头 */
        head = cur->next;
    else
        prev->next = cur->next;        /* 删的是中间/尾 */

    free(cur);
    return head;                       /* 头可能变了 */
}
```

**为什么返回 head**：删头时头会变，调用方必须接收新头。

### 6.4 二级指针版（更短，免特判）

```c
struct node *remove_node2(struct node *head, int id){
    struct node **pp = &head;
    while (*pp && (*pp)->id != id)
        pp = &(*pp)->next;
    if (*pp) {
        struct node *dead = *pp;
        *pp = dead->next;
        free(dead);
    }
    return head;
}
```

`pp` 指向"**应该指向当前节点的那个指针**"——删头时它指向 `head`，删中间时它指向 `prev->next`。**两种情况统一了，不需要 if/else。**

这就是计划里 W5 验收说的"能解释 `Node **` 与 `Node *` 删头的区别"。

### 6.5 `free` 前必须先存 `next`

```c
struct node *next = p->next;   /* 先存 */
free(p);                       /* 再释放 */
p = next;                      /* 最后走 */
```

**`free(p)` 不会改 `p` 的值**——`p` 还指着那块已经"还回去"的内存，这叫**悬垂指针**。`p = p->next` 等于读已释放内存。

## 7. 反转：三指针

### 7.1 正确实现

```c
struct node *reverse(struct node *head){
    struct node *p = head, *q = NULL, *j;
    while (p) {
        j = p->next;      /* ① 先记住下一个 */
        p->next = q;      /* ② 让当前指回前一个 */
        q = p;            /* ③ q 前进到当前 */
        p = j;            /* ④ p 前进到下一个 */
    }
    return q;             /* 循环结束时 p 是 NULL，q 是新头 */
}
```

```
初始：  1 → 2 → 3 → NULL
         p
         q=NULL

第1轮： 1 → NULL      2 → 3 → NULL
         q=1  p=2

第2轮： 2 → 1 → NULL   3 → NULL
              q=2  p=3

第3轮： 3 → 2 → 1 → NULL
                   q=3  p=NULL
```

### 7.2 我的四轮迭代（真实记录）

| 轮次 | 写法 | 症状 | 原因 |
|---|---|---|---|
| 1 | `while((p=p->next)); head=p;` | 编译警告 + 链表被清空 | 循环结束时 `p` 恒为 NULL；一个 `next` 都没改 |
| 2 | 带 `j=head->next` 的版本 | 空链表崩 + 多节点死循环 | `j=head->next` 写在判空之前；指针关系乱了 |
| 3 | `while(!j)` | 链表原样返回 / 单节点崩 | 条件写反了，多节点时循环一次都不进 |
| 4 | 三指针 | ✅ 通过 | — |

**第 1 轮的教训**：`while((p=p->next));` 这种写法看起来"很聪明"，实际上**什么都没做**——它只是把 `p` 推到 NULL 而已。

### 7.3 五个判断点

| # | 判断 | 错了会怎样 |
|---|---|---|
| ① | 不要特判第一个节点 | 跳过首节点会让 `n1->next` 还指着 `n2`，**成环** |
| ② | 条件必须是 `while(p)` | `while(j)` 会在最后一个节点**之前**退出，断链 |
| ③ | `j = p->next` 必须在 `p->next = q` **之前** | 先改就找不到下一个了 |
| ④ | `return q` 不是 `return p` | 循环结束时 `p` 是 NULL |
| ⑤ | 先 `j = p->next` 再动 `p->next` | 顺序错了直接丢链 |

### 7.4 验收

| 场景 | 结果 |
|---|---|
| 空链表 | 返回 NULL，不崩 |
| 单节点 | 返回自己，`next` 仍是 NULL |
| 五节点 | `1 2 3 4 5` → `5 4 3 2 1`，节点数不变 |
| 反转后 `free_list` | 瞬间结束（说明没成环） |

## 8. 快慢指针

### 8.1 `middle`：找中间

```c
struct node *middle(struct node *head){
    struct node *p = head, *q = head;
    while (p && p->next) {        /* 快指针还能走两步吗 */
        p = p->next->next;        /* 快的两步 */
        q = q->next;              /* 慢的一步 */
    }
    return q;                     /* 返回慢的 */
}
```

**原理**：快的走 2 步，慢的走 1 步。快的到终点时，慢的正好在中间。

**实测**：

| n | 返回 | 说明 |
|---|---|---|
| 5 | 第 3 个 | 正中间 |
| 4 | 第 3 个 | 第二个中间 |
| 3 | 第 2 个 | 正中间 |
| 2 | 第 2 个 | 第二个中间 |
| 1 | 自己 | — |
| 0 | NULL | — |

### 8.2 我犯的两个错

**错误 1：返回了 `p`**

```c
return p;    /* ❌ p 是快指针，退出时必为 NULL */
```

**错误 2：循环条件漏了 `p &&`**

```c
while (p->next)          /* ❌ 偶数个节点时崩 */
while (p && p->next)     /* ✅ */
```

**为什么偶数会崩**：偶数个节点时，快指针会正好"跨过"末尾落到 NULL，下一轮判断 `p->next` 就是**解引用空指针**。

```
n=4：p=n1 → n3 → NULL → 💥 p->next
n=5：p=n1 → n3 → n5（停）→ 安全
```

**这就是第三次踩"先解引用再判空"的坑**（前两次：`find`、`middle`）。

### 8.3 `has_cycle`：判环

```c
int has_cycle(struct node *head){
    struct node *p = head, *q = head;
    while (p && p->next) {
        p = p->next->next;
        q = q->next;
        if (q == p) return 1;    /* 追上了 → 有环 */
    }
    return 0;                    /* 快的到终点 → 无环 */
}
```

**和 `middle` 只差一个问题**：

- `middle` 问：快指针**什么时候停**？
- `has_cycle` 问：快指针**会不会追上**慢指针？

**实测**：

| 场景 | 结果 |
|---|---|
| 无环 4 节点 | 0 |
| 空链表 | 0 |
| 尾节点指回第 2 个 | 1 |
| 单节点自指 | 1 |
| 单节点无环 | 0 |

### 8.4 一个有环的链表有多可怕

有环时：

- `print_list` → **死循环**
- `free_list` → **死循环**（释放不完）
- `middle` / `find` → **永不返回**

**测试时造环要记得拆**：

```c
struct node *tail = tail_of(head);   /* 先存尾巴 */
tail->next = head->next;             /* 造环 */
/* ... 测试 ... */
tail->next = NULL;                   /* 用存好的指针拆环 */
free_list(head);
```

我第一次写测试时忘了存尾巴，用 `tail_of()` 去找——结果它自己陷进环里了。

## 9. 内存管理：`free_list`

```c
void free_list(struct node *head){
    struct node *p = head;
    while (p) {
        struct node *next = p->next;   /* 先存 */
        free(p);                        /* 再放 */
        p = next;                       /* 最后走 */
    }
}
```

**顺序不能变**。写成 `free(p); p = p->next;` 就是读已释放内存。

## 10. 易错点总表

| # | 错误 | 症状 | 正确做法 |
|---|---|---|---|
| 1 | `create_node(id, *name)` | `makes pointer from integer` | 传 `name` 不是 `*name` |
| 2 | `push_front(const struct node *head, ...)` | `discards const qualifier` | 存进别人能改的成员，就不能承诺 const |
| 3 | `free_list(const struct node *head)` | `free` 不收 const | 销毁不是只读操作 |
| 4 | `push_back` 照抄头插 | 新节点没接上 | 尾插要走到末尾 |
| 5 | `head = q->next` | **head 变 NULL，链全丢** | `q->next = head` |
| 6 | `while (t->id != id)` | 空链表崩 | `while (t && t->id != id)` |
| 7 | 用 `find(head, id-1)` 找前驱 | 删 id=1 时崩 | 双指针或二级指针 |
| 8 | `struct node *cur, *prev = head;` | cur 未初始化 | 逐个初始化 |
| 9 | else 分支 `free(cur)` 但已 `cur=cur->next` | 释放了错误节点 | 先判断再动 |
| 10 | `prev = head` 而不是 `prev = cur` | 删第三个节点时中间丢失 | `prev = cur; cur = cur->next;` |
| 11 | `reverse` 特判首节点 | 成环 | 不要特判 |
| 12 | `j = p->next` 写在 `p->next = q` 之后 | 丢链 | 先存再改 |
| 13 | `return p` 而不是 `return q` | 返回 NULL | reverse/middle 都返回慢/后指针 |
| 14 | `while (p->next)` | 偶数节点崩 | `while (p && p->next)` |
| 15 | `has_cycle` 漏 `return 0` | 返回值不确定 | 每条路径都要 return |

### 一个万能判断

> **只要循环条件里出现 `p->xxx`，前面必须有 `p`。**

这条能挡掉指针代码里大概一半的崩溃。

### 另一个

> **`a = b->c` 和 `b->c = a` 长得对称，意思相反。**
>
> 左边改**变量**，右边改**内存**。

## 11. 验收自测

### 题 1

`head` 存在栈上还是堆上？节点呢？

**答**：`head` 是局部变量，在**栈**上（8 字节，存第一个节点的地址）；节点是 `malloc` 出来的，在**堆**上。

### 题 2

```c
struct node *p = head;
while (p) p = p->next;
```

循环结束后 `p` 是什么？`head` 有没有变？链表有没有被改？

**答**：`p` 是 `NULL`；`head` 没变；链表**完全没被修改**——`p` 只是在栈上移动，堆上一个字节都没动。

### 题 3

删除中间节点时，为什么要先存 `prev`？

**答**：单向链表没有 `prev` 指针，要改的是"**前一个节点的 `next`**"。只有记住前驱才能改它。删头时前驱不存在（`prev == NULL`），所以要特判。

### 题 4

`free(p)` 之后 `p->next` 还能读吗？

**答**：**不能**。`free` 只是把内存标记为可再分配，不清零，`p` 还指着原地址（悬垂指针）。读它是未定义行为，可能读到旧值、垃圾、也可能崩。

### 题 5

为什么 `reverse` 不需要特判"只有一个节点"？

**答**：单节点时 `p = head`，`p->next = q`（q 是 NULL）→ 节点指向 NULL；`q = p`；`p = j`（NULL）→ 循环结束，返回 `q`（那个节点）。**逻辑自然成立，不需要额外的 if。**

## 14. 一句话

> **链表把"找下一个"从"算地址"变成了"读内存"。**
>
> 数组的 `a[i]` 是算出来的，链表的 `p->next` 是读出来的——后者慢一点，但允许你随时插队、拆队。
>
> 代价是：**每一个 `next` 都由你亲手维护，忘了置 NULL、忘了存 next、方向写反，它就会崩给你看。**
