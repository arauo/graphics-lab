## 1. 本阶段的核心命题

### 1.1 一句话

> **函数改不到调用者的变量，不是因为"值被复制了"，而是因为"你只拿到了值，没拿到地址"。**

### 1.2 三个必答问题

学完 W2 应该能不假思索地回答：

1. `int *p` 里的 `*` 是什么？（答：声明时的类型标记，不是解引用）
2. `*p = 5` 改的是谁？（答：`p` 指向的那块内存）
3. 为什么 `my_strcpy` 必须复制 `'\0'`？（答：不复制它，结果就不是字符串）

## 2. 地址与解引用

### 2.1 `&` 和 `*` 是一对互逆操作

```c
int x = 10;

int *p = &x;   /* &x：取出 x 的地址，存进 p */
printf("%p", (void*)p);    /* 打印 p 本身：一个地址 */
printf("%d", *p);          /* *p：顺着地址找到那块内存，读出 10 */
```

| 写法 | 含义 | 结果 |
|---|---|---|
| `x` | 变量的值 | `10` |
| `&x` | 变量的地址 | `0x61fe14`（示意） |
| `p` | 指针的值（也就是地址） | `0x61fe14` |
| `*p` | 指针指向的值 | `10` |

**记忆法：`&` 是"它在哪"，`*` 是"去那儿看看"。**

### 2.2 指针变量的类型含义

```c
int    *p;   /* p 是"指向 int 的指针"，它存的地址，那里存着一个 int */
char   *s;   /* s 是"指向 char 的指针" */
double *d;   /* d 是"指向 double 的指针" */
```

**关键：指针的类型决定了三件事**

1. `*p` 时读几个字节（`int*` 读 4，`char*` 读 1）
2. `p + 1` 时前进几个字节（这是 W3 的内容）
3. 编译器允许你做什么操作

### 2.3 最容易混的：`int *tmp` 与 `*tmp`

```c
int *tmp;    /* 声明：tmp 是一个 int*，它自己是个变量 */
*tmp = 5;    /* 使用：去 tmp 指向的地方写 5 */
```

**同一个 `*`，位置不同，含义完全不同：**

| 位置 | 含义 |
|---|---|
| 声明中的 `*`（`int *tmp`） | 类型的一部分，告诉编译器"tmp 存的是地址" |
| 表达式中的 `*`（`*tmp = 5`） | 运算符，解引用 |

**这就是 `int *tmp = a;` 和 `*tmp = a;` 只差一个星号、却完全不是一回事的原因。**

### 2.4 `int *tmp = a` 不是二级指针

写 swap 时写过这段：

```c
int *tmp = a;    /* tmp 和 a 是同一类型：都是 int* */
```

**tmp 是普通的一级指针，和 a、b 地位相同。**

反证：如果 tmp 是二级指针 `int **tmp`，那么下一句 `*tmp = *b;` 中：

- `*tmp` 的类型是 `int*`（解一层）
- `*b` 的类型是 `int`
- `int* = int` → 类型不匹配，编译报错

真二级指针长这样：

```c
int  x = 10;
int *p = &x;
int **pp = &p;     /* &p 的类型是 int**，所以 pp 是二级指针 */
printf("%d", **pp);  /* 10，解两层 */
```

## 3. 值传递 vs 传地址（swap 四种写法）

### 3.1 wrong1：值传递

```c
void swap_wrong1(int a, int b) {
    int tmp = a;
    a = b;
    b = tmp;
    /* 函数内 a、b 确实换了 —— 但那是副本 */
}
```

调用 `swap_wrong1(x, y)` 时发生的事：

```
main 里:        x=1      y=2
                 ↓ 复制   ↓ 复制
函数里:     a=1  b=2   ← 两块新内存，值碰巧相同
                 ↓ 交换
               a=2  b=1   ← 确实换了
                 ↓ return
             副本销毁
main 里:        x=1      y=2   ← 纹丝不动
```

**病因：函数拿到的是"值"，不是"地址"。**

### 3.2 wrong2：换了纸条，没换房子

```c
void swap_wrong2(int *a, int *b) {
    int *tmp = a;
    a = b;
    b = tmp;
    /* 指针变量本身互换了，但它俩指向的内存没动 */
}
```

```
调用前:  a ──→ x        b ──→ y
调用后:  a ──→ y        b ──→ x
                （x、y 的值谁也没变）
```

**病因：`a = b` 改的是指针变量（纸条），不是它指向的东西（房子）。**

### 3.3 wrong3：用地址当临时容器

```c
void swap_wrong3(int *a, int *b) {
    int *tmp = a;   /* tmp 指向 x */
    *tmp = *b;      /* x = 2，原来的 1 永久消失 */
    *b = *a;        /* y = 2 */
    /* 结果 x=2 y=2 */
}
```

**病因：`tmp` 存的是地址，不能拿它当"临时值"用。** 第一句写下去之后，旧值就没有备份了。

### 3.4 ok：解引用改原件

```c
void swap_ok(int *a, int *b) {
    int tmp = *a;   /* 存的是"值"，不是地址 */
    *a = *b;
    *b = tmp;
}
```

**关键差别：`int tmp = *a`（存值）而不是 `int *tmp = a`（存地址）。**

### 3.5 四种写法对照

| 写法 | 中间变量 | 改的是 | 结果 |
|---|---|---|---|
| `wrong1(int a, int b)` | `int tmp` | 副本 | `x=1 y=2` ❌ |
| `wrong2(int *a, int *b)` | `int *tmp` | 指针本身 | `x=1 y=2` ❌ |
| `wrong3(int *a, int *b)` | `int *tmp` | 指向的内存（但覆盖了） | `x=2 y=2` ❌ |
| `swap_ok(int *a, int *b)` | `int tmp` | 指向的内存（有备份） | `x=2 y=1` ✅ |

### 3.6 核心公式

> **能改到原件 = 拿到地址 + 用 `*` 解引用**

拆开看：

- **拿到地址**是手段（`&x` 或形参 `int *a`）
- **`*` 才是动作**（`*a = ...` 才真的写进去）

只做第一步（wrong2）不够，因为只换了指路牌；两步都做（ok）才行。

## 4. 字符串：`char` 数组 + `'\0'` 约定

### 4.1 C 没有字符串类型

C 语言里**不存在** `string` 这种类型。所谓"字符串"，是两条约定拼出来的：

> **字符串 = `char` 数组 + 最后一个字节必须是 `'\0'`**

### 4.2 `"hello"` 的内存长什么样

| 下标 | 0 | 1 | 2 | 3 | 4 | 5 |
|---|---|---|---|---|---|---|
| 字符 | `h` | `e` | `l` | `l` | `o` | `'\0'` |
| 字节值 | 104 | 101 | 108 | 108 | 111 | **0** |

**六个字节，不是五个。** 多出来的那个 `0` 是结束标记。

两个极易混淆的写法：

| 写法 | 值 | 说明 |
|---|---|---|
| `'\0'` | 0 | 空字符（结束标记） |
| `'0'` | 48 | 字符"零" |

**`'\0'` 是数字 0，`'0'` 是 48。一个是结束标记，一个是普通字符。**

### 4.3 三种写法对比

```c
char a[] = "hello";          /* 数组：6 字节，可改，自动带 '\0' */
char *p  = "hello";          /* 指针指向只读段：改了会崩 */
const char *q = "hello";     /* 最安全的写法：明确告诉编译器"只读" */
```

| 写法 | 存储位置 | 可改吗 | sizeof |
|---|---|---|---|
| `char a[] = "hello"` | 栈（可读写） | ✅ `a[0]='H'` 合法 | 6 |
| `char *p = "hello"` | 只读数据段 | ❌ 改了段错误 | 8（指针大小） |
| `const char *q` | 只读数据段 | ❌ 编译器直接拦 | 8 |

### 4.4 `sizeof` 与 `strlen` 的区别

```c
char a[] = "hello";
char *p  = "hello";

sizeof(a)   /* 6 —— 数组的总字节数 */
sizeof(p)   /* 8 —— 指针的大小，跟字符串长度无关 */
strlen(a)   /* 5 —— 真实字符数，不含 '\0' */
strlen(p)   /* 5 —— 一样 */
```

**关键陷阱：数组传参后退化，`sizeof` 失效**

```c
void f(char s[]) {
    printf("%d\n", (int)sizeof(s));   /* 8，不是字符串长度！ */
}
```

**因为形参里的 `char s[]` 等价于 `char *s`。**

**这正是 `strlen` 存在的理由：函数拿不到长度信息，只能一路扫到 `'\0'`。**

### 4.5 字面量为什么不能写（实测）

```c
char *s = "hello";
s[0] = 'H';        /* 编译能过、零警告，运行时崩掉 */
```

实测（Windows / MinGW GCC 16.2.0）：

```
[指针] s 指向的地址 = 00007ff75d72a000      ← 高地址，在 exe 映像里
[数组] a 的地址     = 000000e317dffad2      ← 低地址，在栈上

[数组] 改完 a = Hello                        ← 数组成功了

[指针] 准备执行 s[0] = 'H' ...
--- 运行退出码: -1073741819  /  0xC0000005 ---
```

**`0xC0000005` 是 Windows 的「访问冲突」（Access Violation），Linux 上叫 `Segmentation fault`。**

三个关键事实：

| # | 事实 | 说明 |
|---|---|---|
| 1 | **编译器不拦** | C 里字面量的类型是 `char[]`，不是 `const char[]`（历史遗留）；C 标准只说这是「未定义行为」，不要求报错 |
| 2 | **拦你的是操作系统** | CPU 的 MMU 检测到「写只读页」→ 抛异常 → 系统终止进程 |
| 3 | **C++ 会拦** | C++ 把字面量定为 `const char[]`，`char *s = "hello"` 直接编译错误 |

**想提前发现，编译时加 `-Wwrite-strings`：**

```
warning: initialization discards 'const' qualifier from pointer target type
```

**真正危险的不是崩溃，而是「不崩」。** 在没有内存保护的平台（单片机、部分嵌入式），字面量可能被静默改掉，变成「随机出现的怪 bug」——比直接崩溃难查一百倍。

### 4.6 复制机制：为什么数组能改

**`char a[] = "hello"` 做的是「复制一份」：**

```
.rodata（只读）:  h  e  l  l  o  \0     ← 模板，程序结束前一直在，没人再碰
栈（可写）:        h  e  l  l  o  \0     ← a 指向这里，启动时复制出来
```

**复制发生在函数进入、栈帧建立的那一刻**，由编译器生成的初始化代码完成，不是某条语句触发的。

| 写法 | 内存里有几份 | 指向哪 | 能改 |
|---|---|---|---|
| `char a[] = "hello"` | **2 份** | 栈上副本 | ✅ |
| `char *s = "hello"` | **1 份** | `.rodata` | ❌ 会崩 |

这顺便解释了 `sizeof` 的差别：`sizeof(a)` = 6（数组自己知道多大），`sizeof(p)` = 8（指针只知道自己 8 字节）。

**口诀：**

> **要改，用数组；不改，加 `const`。**

**一句话记法：`char *s = "hello"` 是「借书」，`char a[] = "hello"` 是「抄一份」。借的书不能在上面写字，抄的那份随便改。**

### 4.7 两个直接推论

**推论 1：栈上的东西不能往外传地址**

```c
char *bad(void) {
    char buf[32] = "hello";
    return buf;            /* ❌ 返回了一个即将销毁的地址 */
}
```

编译器会警告：

```
warning: function returns address of local variable [-Wreturn-local-addr]
```

因为 `buf` 在 `bad` 的栈帧里，函数一返回那块内存就作废，调用者拿到的是野指针。

**两种正确写法：**

```c
char *ok(void) {
    return "hello";        /* ✅ 字面量在 .rodata，永久有效 */
}

void ok2(char *dst) {      /* ✅ 让调用者提供缓冲区 */
    my_strcpy(dst, "hello");
}
```

**推论 2：数组不能整体赋值，也不能用 `==` 比较**

```c
char a[] = "hello";
char b[] = "world";

b = a;          /* ❌ 编译错误：数组名不是左值 */
if (a == b)     /* ⚠️ 能编过，但比的是地址，恒为假 */
my_strcpy(b, a);/* ✅ 只能逐字节复制 */
```

**因为数组名代表「那块内存本身」，不是「一个指向哪里的变量」。** 内存不能整体搬家。

**这也解释了为什么 C 标准库有一整套 `strxxx` 函数——数组自己做不到这些事。**

## 5. `my_strlen` 与 `my_strcpy`

### 5.1 `my_strlen`

```c
int my_strlen(const char *s) {
    int i = 0;
    while (*s != '\0') {
        i++;
        s++;
    }
    return i;
}
```

**逻辑：一直往前走，碰到 `'\0'` 停，走了几步就是多长。**

不直接写 `while (*s++)` 是因为那样最后会多走一步，得再减一次，容易出错。

### 5.2 `my_strcpy` 第一版：错在哪

```c
char *my_strcpy(char *dst, const char *src) {
    for (; *src != 0; src++ && dst++) {
        *dst = *src;
    }
    src++ && dst++;      /* ← 错误 1 */
    *dst = *src;         /* ← 错误 2 */
    return dst;          /* ← 错误 3 */
}
```

实际输出：

```
buf = hello%         ← 多了个 %（内存垃圾）
len = 7              ← 应该是 0
```

**三个错误：**

| # | 错误 | 后果 |
|---|---|---|
| 1 | 循环结束后又 `++` 了一次 | 跳过了 `'\0'` |
| 2 | 复制的是 `'\0'` **后面**那个字节 | 把垃圾写进去，且真正的 `'\0'` 没写入 |
| 3 | `return dst` 返回末尾 | 调用者拿到的是"结尾"，不是"开头" |

**为什么第一次调用看起来"差不多对"：** `printf("%s")` 会一直读，直到碰巧遇到一个 0。所以输出成了 `hello%`。

**为什么第二次调用完全没生效：** `my_strcpy(buf, "")` 时循环一次都不执行，然后去复制垃圾字节，**`buf[0]` 从头到尾没被写过**，里面还是上次的 `hello%`。

### 5.3 正确写法 A（直白版）

```c
char *my_strcpy(char *dst, const char *src) {
    char *ret = dst;              /* 记住开头 */

    while (*src != '\0') {        /* '\0' 本身不搬 */
        *dst = *src;
        dst++;
        src++;
    }

    *dst = '\0';                  /* 单独补上结束符 ← 关键 */
    return ret;                   /* 返回开头 */
}
```

**两条输入都覆盖到：**

| 输入 | 循环搬的 | 然后 | 结果 |
|---|---|---|---|
| `"hello"` | `h e l l o` | 补 `'\0'` | ✅ |
| `""` | 一个都不搬 | 直接在 `dst[0]` 写 `'\0'` | ✅ 长度 0 |

### 5.4 正确写法 B（精炼版）

```c
char *my_strcpy(char *dst, const char *src) {
    char *ret = dst;
    while ((*dst++ = *src++))
        ;
    return ret;
}
```

**为什么它能自动复制 `'\0'`：**

```c
while ( (*dst++ = *src++) )
              ↑
     赋值表达式的值 = 刚复制的那个字节
```

| 复制的字节 | 表达式的值 | 循环 |
|---|---|---|
| `'h'` | 104 | 继续 |
| `'o'` | 111 | 继续 |
| `'\0'` | **0** | **停止** |

**关键：`'\0'` 是在"判断为假"之前就被写进去的。**

```
先赋值：*dst = '\0'    ← 已经写进 dst 了
再判断：表达式的值 = 0  → 退出
```

**"复制"和"判断"共用同一次赋值，所以不可能漏掉结束符。**

### 5.5 两种写法对比

| | 写法 A | 写法 B |
|---|---|---|
| 复制 | 循环体里 | 条件里 |
| 前进 | 循环体里两句 | 后缀 `++` 自动 |
| 补 `'\0'` | 单独一行 | 自动 |
| 可读性 | 高 | 需要熟悉后缀 `++` |
| 标准库 | 也有 | **K&R 的 `strcpy` 就是这么写的** |

**两种都对。A 好读，B 要能看懂（读源码时会遇到）。**

### 5.6 那个双括号在干嘛

```c
while ((*dst++ = *src++))    ← 两层括号
```

**外层括号是告诉编译器："我知道自己在条件里写赋值，别警告"。**

只写一层：

```
warning: suggest parentheses around assignment used as truth value [-Wparentheses]
```

**这是 C 语言的历史教训**：很多人想写 `==` 却写成了 `=`，`if (x = 5)` 永远为真。编译器现在默认怀疑这种情况，加括号 = 声明"我是故意的"。

### 5.7 危险提示：缓冲区溢出

```c
char buf[5];
my_strcpy(buf, "hello world");   /* 溢出 7 个字节，栈被踩坏 */
```

**两种写法都不知道 `dst` 有多大。** 这正是标准库后来加 `strncpy` / `strlcpy` 的原因。

**真实项目里 `strcpy` 是禁用函数。** 现在先用，但要知道这个坑。

## 6. `const` 的四象限

### 6.1 三个作用

`const char *s` 的含义是"**我只读，不会改**"。它有三层作用：

1. **编译器拦截**：`*s = 'X';` → `error: assignment of read-only location`
2. **函数签名即文档**：看到 `const char*` 就知道这个参数不会被改
3. **能接收 const 实参**：`const char*` 形参能接收 `char*`，反过来不行

### 6.2 四象限表

```c
const char *s;              /* 内容只读，指针可动 */
char * const s;             /* 指针只读，内容可改 */
const char * const s;       /* 都不可动 */
char *s;                    /* 都可动 */
```

**读法：`const` 在 `*` 左边 = 内容只读；在 `*` 右边 = 指针只读。**

### 6.3 标准库的规律

> **只读源参数加 `const`，写入目标不加。**

```c
char *strcpy(char *dst, const char *src);
/*            ↑ 要写      ↑ 只读      */
```

`dst` 是要被写入的，所以不能 const；`src` 只读，所以必须 const。

**我们的 `my_strcpy(char *dst, const char *src)` 完全遵循这个规律。**

## 7. gdb 实操

### 7.1 上次为什么失败

| 失败现象 | 真正原因 |
|---|---|
| 程序直接跑完，没停 | 只敲了 `run`，**没先 `break main`** |
| `Excess command line arguments ignored` | 从聊天复制 `-ex "break ..."` 时，**英文引号被替换成中文引号 `“”`**，参数被拆散 |

**教训：只要命令里有引号，复制就一定会出问题。改成全程交互式，一条条敲。**

### 7.2 零引号启动流程

```powershell
.\build.bat src\gdb_lab.c
gdb build\gdb_lab.exe
```

进去后先设两个：

```
(gdb) set pagination off
(gdb) set confirm off
```

- `pagination off`：输出多了不会卡在 `--More--`
- `confirm off`：`quit` 不再问 "Quit anyway?"

### 7.3 练习 A：看"副本"

```
(gdb) break main
(gdb) run
(gdb) next
(gdb) next
(gdb) p x
$1 = 10
(gdb) p &x
$2 = (int *) 0x61fe14        ← 记住这个地址

(gdb) break add_one
(gdb) continue
(gdb) p n
$3 = 10
(gdb) p &n
$4 = (int *) 0x61fdf0        ← 和 &x 不一样！
```

**这是全场最重要的一次对比：**

```
&x = 0x61fe14
&n = 0x61fdf0     ← 另一块内存，只是值碰巧也是 10
```

**值传递的真相：`n` 是另一个变量。**

再看调用栈：

```
(gdb) bt
#0  add_one (n=10) at src/gdb_lab.c:4
#1  main () at src/gdb_lab.c:18
```

### 7.4 练习 B：看"原件"

```
(gdb) break add_one_ptr
(gdb) continue
(gdb) p p
$7 = (int *) 0x61fe10
(gdb) p &y
$8 = (int *) 0x61fe10        ← 一模一样！
```

**这次 `p` 里装的就是 `y` 的地址，不是副本。**

```
(gdb) p *p
$9 = 10
(gdb) next
(gdb) next
(gdb) p *p
$10 = 11
(gdb) finish
(gdb) p y
$11 = 11                     ← 真的变了
```

### 7.5 练习 C：看内存

```
(gdb) x/4dw &x
0x61fe14:   10   -2   4200784   0
```

拆解：`x` = 查看内存 / `4` = 看 4 组 / `d` = 十进制 / `w` = 每组 4 字节（一个 int）

### 7.6 `set var` 是**写**内存

| 命令 | 动作 |
|---|---|
| `p x` | 读 |
| `x/4dw &x` | 读 |
| `set var x = 999` | **写** |

它做三步：

```
① 查符号表：x 在哪 → 0x61fe14，类型 int（4 字节）
② 把 999 编码成 0x000003E7
③ 写入那 4 个字节
```

**等价写法（证明它就是内存写入）：**

```
(gdb) set var x = 999
(gdb) set {int}0x61fe14 = 999      ← 直接给地址，连变量名都不用
```

**能改什么：** 普通变量、`*p`、`p` 本身、`arr[2]`、`s.age`

**改不了什么：**

- **`-O2` 优化过的变量**：可能只存在于寄存器，`set var` 无效
- **只读段**：`char *s = "hello"` 里的内容，改了会段错误

**`set var` 只影响这一次运行**，不会改源文件，重新运行就恢复。

### 7.7 命令小抄

| 命令 | 作用 |
|---|---|
| `break main` | 在 main 开头下断点（**每次必先做**） |
| `run` | 开始运行，停在断点 |
| `next` | 执行一行，不进入函数 |
| `step` | 执行一行，进入函数 |
| `finish` | 跑完当前函数，返回调用者 |
| `continue` | 运行到下一个断点 |
| `p 变量` | 打印值 |
| `p &变量` | 打印地址（**对比副本的关键**） |
| `bt` | 显示调用栈 |
| `x/4dw &x` | 看内存 |
| `set var x = 999` | 改值 |
| `info locals` | 列出当前函数所有局部变量 |
| `delete` | 删掉所有断点 |

### 7.8 三个 Windows 坑

| 坑 | 表现 | 解法 |
|---|---|---|
| 中文乱码 | gdb 控制台是 GBK，源文件 UTF-8 | printf 全用英文 |
| 程序卡住 | 在等输入或死循环 | `Ctrl + C` 中断 |
| 没带 `-g` | 显示 `No symbol table` | 编译时加 `-g`（build.bat 里有） |

## 8. `build.bat` 参数化

### 8.1 为什么改

原来固定编译 `src\swap.c`，文件一多就得每次改脚本。

### 8.2 新版内容

```bat
@echo off
if not exist build mkdir build
if "%~1"=="" (
    echo Usage: build.bat src\filename.c
    exit /b 1
)
gcc -Wall -Wextra -g -fexec-charset=GBK "%~1" -o "build\%~n1.exe"
if errorlevel 1 exit /b 1
echo Build OK: build\%~n1.exe
```

### 8.3 两个新符号

| 符号 | 含义 | 例 |
|---|---|---|
| `%~1` | 第一个参数，去掉引号 | `src\strlen.c` |
| `%~n1` | 第一个参数的**文件名部分**（无路径无扩展名） | `strlen` |

**所以 `build\%~n1.exe` 会自动变成 `build\strlen.exe`。**

| 命令 | 产物 |
|---|---|
| `.\build.bat src\hello.c` | `build\hello.exe` |
| `.\build.bat src\swap.c` | `build\swap.exe` |
| `.\build.bat src\strlen.c` | `build\strlen.exe` |
| `.\build.bat`（无参数） | 打印 Usage，退出 |

### 8.4 一个提醒

`build\` 里会不断堆积历史 `.exe`，**编译只生成、不清理**。想彻底重来：

```powershell
rmdir /s /q build
```

## 9. 易错点总表

| # | 错误 | 正确做法 |
|---|---|---|
| 1 | `int *tmp = a` 以为是二级指针 | 它就是普通一级指针，和 a 同类型 |
| 2 | `a = b` 以为换了指向的内容 | 只换了指针变量本身，要用 `*a = *b` |
| 3 | `int tmp = a`（a 是指针） | 想存值要写 `int tmp = *a` |
| 4 | `my_strcpy` 漏复制 `'\0'` | 循环结束后单独补，或用 `while ((*dst++ = *src++))` |
| 5 | `return dst`（已走到末尾） | 先 `char *ret = dst;` 最后返回 ret |
| 6 | `while (*p = *q)` 只写一层括号 | 写 `while ((*p = *q))`，否则编译器警告 |
| 7 | `char *p = "hello"` 后改内容 | 改 `char a[] = "hello"` 的 `a[0]`，或加 `const` |
| 8 | 用 `sizeof` 求形参数组的长度 | 形参数组退化成指针，`sizeof` 失效，只能 `strlen` |
| 9 | `src++ && dst++` 当更新表达式 | 用逗号 `src++, dst++`，`&&` 有短路且报警告 |
| 10 | 改 `.c` 后忘重新编译 | `.exe` 不会自动更新，必须跑 `.\build.bat` |
| 11 | 写字符串字面量：`char *s="hello"; s[0]='H';` | 编译能过、运行时崩（`0xC0000005`）。要改用 `char a[]="hello"`，不改加 `const` |
| 12 | 返回局部数组地址：`char *f(){char b[9];return b;}` | 栈帧销毁后就是野指针。返回字面量，或让调用者传缓冲区 |

### 一个万能判断

**看到 `*` 先问：这是声明里的，还是表达式里的？**

- 声明里（`int *p`）→ 类型标记
- 表达式里（`*p = 5`）→ 解引用（W2）
- 表达式里（`a * b`）→ 乘法（看两边是不是数字）

## 10. 验收自测（5 题）

不看书，先自己答。

### 题 1

```c
void f(int *p) { *p = 99; }
int n = 1;
f(&n);
printf("%d", n);
```

输出什么？

### 题 2

```c
void f(int *p) { p = NULL; }
int n = 1;
int *q = &n;
f(q);
printf("%p", (void*)q);
```

`q` 会变成 NULL 吗？

### 题 3

```c
char a[] = "hello";
char *p  = "hello";
printf("%d %d", (int)sizeof(a), (int)sizeof(p));
```

输出什么？

### 题 4

`my_strcpy(dst, "")` 之后，`dst[0]` 是什么？

### 题 5

```c
char *s = "hello";
s[0] = 'H';
```

会发生什么？

---

### 答案

**题 1** → `99`
因为 `p` 拿到了 `&n`，`*p = 99` 写的就是 `n` 那块内存。

**题 2** → **不会**，`q` 还是 `n` 的地址
`p = NULL` 只改了形参 `p` 这个副本。要让 `q` 变 NULL，得传 `&q` 且形参写成 `int **p`。

**题 3** → `6 8`
`a` 是数组，6 字节；`p` 是指针，8 字节（x64）。**`sizeof` 看容器，`strlen` 看内容。**

**题 4** → `'\0'`（值是 0）
空字符串也要写入一个结束符，否则 `dst` 不是合法字符串。

**题 5** → **运行时崩溃（`0xC0000005` 访问冲突 / 段错误）**
字面量在 `.rodata` 只读段，写它会被 MMU 拦截、进程终止。
**编译期不报错**（C 的历史遗留），加 `-Wwrite-strings` 才有警告，C++ 才直接报错。
**实测证据**：`.rodata` 地址 `0x00007ff7...`（高）vs 栈地址 `0x000000e3...`（低），退出码 `-1073741819`。
**正确写法**：`char a[] = "hello"; a[0] = 'H';`

## 11. W2 要懂到什么程度

### 必须能徒手写出来

- `void swap(int *a, int *b)`
- `int my_strlen(const char *s)`
- `char *my_strcpy(char *dst, const char *src)`（两种写法至少会一种）

### 必须能讲清楚

- `&` 和 `*` 的关系
- 值传递为什么换不了
- 字符串为什么要 `'\0'`
- `sizeof` 和 `strlen` 的区别
- 字面量为什么不能写、数组为什么能改（复制机制）
- 函数为什么不能返回局部数组的地址
- `const char *` 和 `char * const` 的区别

### 现在不用懂（W3 / 以后）

- 指针算术（`p + 1` 的步长）
- 数组名退化后的各种规则
- 函数指针
- 二级指针的真正用途（`Node **head`）
- 严格别名、未定义行为
